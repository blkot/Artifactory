# Phase 5.15 + 5.16: Silent Token Refresh & Documentation — Design

Date: 2026-04-29

## Phase 5.15: Silent Token Refresh

### Current Behavior
On 401, `client.js` immediately clears auth and fires `artifactory-auth-expired`.

### Target Behavior
On 401, silently attempt `POST /auth/refresh` with the stored refresh token. If it succeeds, retry the original request with the new access token. If it fails, clear auth as before.

### Design: Refresh Lock

`client.js` gains a module-level `refreshPromise` variable (null when no refresh in-flight).

When a request gets 401:
1. If the failing request IS `/auth/refresh`, skip refresh (no infinite loop).
2. Look up stored refresh token from localStorage. If none → logout.
3. If `refreshPromise` is null, create one: call `/auth/refresh`, save new access token, return.
4. If `refreshPromise` exists, `await` it (multiple requests queue on the same promise).
5. After the shared promise resolves, retry the original request with the new token.
6. If the shared promise rejects, clear auth.

### Retry Mechanics
The retry reconstructs the fetch call from the original arguments. For requests with a consumed `body` stream, the caller must pass a cloneable body — `request()` will handle JSON bodies by re-stringifying.
