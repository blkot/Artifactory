# Phase 5.14: Token Lifecycle Hardening — Design

Date: 2026-04-29

## Summary

Add a revoked-token denylist so that explicit logout invalidates refresh tokens. Each login (web, mobile) gets independent tokens; revoking one does not affect the other.

## What Changes

### New Model: RevokedToken

```
id             INTEGER PK
token_jti      VARCHAR(64) UNIQUE NOT NULL   -- JWT ID claim
revoked_at     DATETIME NOT NULL
reason         VARCHAR(50)                   -- "logout" | "rotation" | "admin"
```

### JWT Claims

Add `jti` (UUID4 hex) to both access and refresh tokens at creation time.

### New Dependency: check_token_not_revoked()

- Queries `RevokedToken` by `jti`.
- Applied to every authenticated request (access token check).
- Applied to `POST /auth/refresh` before issuing a new access token.

### New Endpoint: POST /api/v1/auth/logout

- Accepts `refresh_token` in request body.
- Validates the token.
- Inserts its `jti` into `RevokedToken` (idempotent — ignores duplicate).
- Returns 204.

### Modified: POST /api/v1/auth/refresh

- After validating the refresh token, checks denylist before issuing new access token.

### Frontend

- Logout button calls `POST /api/v1/auth/logout` with stored refresh token before clearing local auth state.

## What Does NOT Change

- No refresh token rotation (deferred for public multi-user deployment).
- Access tokens remain short-lived (60 min) and are not individually revocable — they expire naturally.
- Multi-device sessions unaffected by independent logouts.

## Migration Path to Rotation

When rotation is needed later:
1. On refresh: mark the old refresh token `jti` as revoked (reason = "rotation"), issue new refresh token.
2. Handle concurrent-tab race: if a refresh token is already revoked, revoke the entire token family.
3. `RevokedToken` table is already in place — no schema change needed.

## Test Plan

- Logout inserts revocation record.
- Refresh with a revoked token returns 401.
- Authenticated request with a revoked access token returns 401.
- Double logout is idempotent.
- Independent sessions survive each other's logout.
